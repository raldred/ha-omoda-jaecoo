# 0.6.0 — preview

First packaged preview of the native Omoda / Jaecoo Home Assistant integration. This is not a claim of universal model compatibility or production-ready vehicle controls. It is installable as a **HACS custom repository** or using the component ZIP; default-catalogue inclusion is a separate review process.

## Included integration features

- Native Home Assistant config, reauthentication and reconfiguration flows, with email/password, phone/password, email OTP and phone OTP sign-in. **Only email/password has been live-validated against the target account/backend.** The other three methods have offline coverage, not a live-success claim.
- Cloud-reported vehicle, battery, charging and status sensors, binary sensors, opt-in location tracking and native lock/climate controls. Home Assistant **2026.7.1 or newer** is required.
- Read-only `omoda_jaecoo.refresh_status` action to request a passive cloud status refresh for an explicitly selected account entry. Administrator callers and trusted automations are supported; overlapping manual requests are refused and manual refreshes have a 10-second cooldown. This is **not a vehicle ping/wake command**: it does not send a wake, horn, locate, lock or climate operation. Implementation is covered by offline tests; live HA/vehicle verification of this new action remains pending.
- Control PIN is separate from the account password, optional for telemetry and used only after controls are explicitly enabled and a command is requested. Startup, setup, polling and read-only refresh do not verify a PIN or send physical commands. Failed/inconclusive PIN checks block controls until explicit reconfiguration; commands are not automatically retried.
- Native command feedback distinguishes REST request acceptance from a reported state. **Accepted does not mean completed.** Telemetry is not optimistically switched to the requested final state, and this REST-only integration does not provide sequence-correlated terminal MQTT acknowledgements.
- After an accepted explicit control command, bounded passive status checks improve feedback without repeating the command or implicitly waking the car.

## Data and safety caveats

Cloud telemetry and its source timestamps can be cached or stale. A refresh asks the cloud for its latest available report; it does not guarantee a fresh measurement from the car and does not automatically wake it. The normal polling schedule is unchanged.

The observed charging remaining-time field is interpreted in **minutes**, as proven for the target telemetry. This is not a guarantee that every model or backend uses the same schema or units.

GPS/location reads are optional and disabled by default. Enabling them records sensitive last-reported location data; protect HA storage and backups. Raw location payload structure/depth has **not been verified for the target vehicle**, so this preview does not claim complete location coverage. Diagnostics remain structurally allowlisted rather than exposing raw telemetry, GPS or credentials.

This is unofficial, model/backend-specific software. There is **no claim of CarLinko support, all-Chery support, all Omoda/Jaecoo model coverage, or universal command completion**. Account/session operations may affect the official app session. Only use an account and vehicle you are authorized to access. Supervised PIN, permissions, lock/climate and session checks remain necessary before relying on controls.

## Installation and artifacts

For manual installation, extract `omoda_jaecoo.zip` into Home Assistant's `/config/custom_components/`, producing `/config/custom_components/omoda_jaecoo/manifest.json`, then restart HA. Do not nest the domain directory twice. Back up the previous installation before replacing it.

HACS uses normal repository/source installation, not ZIP-release mode. Add `https://github.com/raldred/ha-omoda-jaecoo` as a custom repository of type Integration. Preview versions may require enabling beta releases in HACS.

The release builder reads the selected **committed Git tree**, not uncommitted local changes. It emits a deterministically ordered component-only ZIP, `SHA256SUMS` (for the ZIP and metadata) and `release.json` containing the source commit SHA, manifest version, archive filename, file count and archive SHA-256. Verify with `sha256sum --check SHA256SUMS` in the artifact directory. Apps, captures, research/analysis, automated tests, private keys and development environments are not ZIP distribution content. The original prototype probe has been retired; the source repository retains only the integration's synthetic regression tests and release tooling.

## Verification status

Packaging and integration tests run offline with synthetic fixtures. Release preparation performs no live Home Assistant, vehicle or OEM requests, no credential checks, and no physical-command validation. This preview must not be read as confirmation of live behavior for the new refresh action or any unvalidated authentication/control path.
