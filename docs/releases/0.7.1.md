Stable 0.7.1 brings rapid cabin heating and optional scheduled conditioning to HACS, with clearer rear-window permission checks.

- Rapid heating is confirmed working on the tested E5. Use `omoda_jaecoo.rapid_heat` to start or stop cabin heating with a vehicle-supported temperature and duration.
- The dedicated rear-window switch and the explicit `omoda_jaecoo.rear_defrost_with_climate` action have separate permission checks, with no automatic fallback. The coupled action starts or reconfigures cabin heating; turning it OFF also stops cabin climate. It requires explicit acknowledgement.
- Administrators can check rear-window permissions with `omoda_jaecoo.diagnose_rear_defrost_permissions`. It uses only a confirmed cached session, without logging in, refreshing credentials, checking a PIN or sending an actuator command.
- The optional [conditioning blueprint](https://github.com/raldred/ha-omoda-jaecoo/blob/main/docs/scheduling.md) needs a separate import. HACS doesn't install it, and nothing is scheduled automatically.

Both rear-window routes are vehicle- and permission-dependent and have not been physically validated. The tested E5 denies rear-window remote permission despite fitted hardware. Cloud acceptance doesn't prove the car acted, and no wake command is implemented.

Controls require opt-in and a saved control PIN. Hybrid conditioning may start the engine, so test outdoors, never in a garage.

Requires Home Assistant 2026.7.1 or newer. Install stable 0.7.1 from HACS without enabling beta versions. [Setup and limitations](https://github.com/raldred/ha-omoda-jaecoo#installation).
