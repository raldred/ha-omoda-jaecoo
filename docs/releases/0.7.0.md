Rapid heating, an independent rear-window defrost switch, and an optional scheduling blueprint.

- `omoda_jaecoo.rapid_heat` requests the car's own one-touch cabin heating, or stops it. The seat, steering-wheel and window switches the route accepts are never sent, so it only asks for cabin heating.
- **Rear-window defrost** switch, created only for cars that actually report a rear-window heater.
- Optional [scheduled conditioning blueprint](https://github.com/raldred/ha-omoda-jaecoo/blob/main/docs/scheduling.md) with fail-closed cold, presence, battery and manual-enable gates. Nothing is scheduled until you create an automation from it, and the blueprint is imported or copied manually—HACS doesn't install it.
- Temperatures and run durations are refused unless your vehicle reports them as supported.

Requires remote controls to be enabled and a saved control PIN. Conditioning can start the engine on hybrids, so test outdoors, never in a garage. The cloud accepting a request doesn't prove the car acted: check the Command status sensor and the vehicle. Nothing is ever retried automatically.

Requires Home Assistant **2026.7.1 or newer**. Install from HACS or use the ZIP below. [Setup instructions and current limitations](https://github.com/raldred/ha-omoda-jaecoo#installation).
